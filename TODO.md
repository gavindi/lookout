## Phase 2 — Mail advanced (roadmap)

- [x] Message delete - move-to-Trash via IMAP MOVE (RFC 6851) where supported, else COPY + STORE `\Deleted` + EXPUNGE - backs the toolbar's Delete button
- [x] Move-to-folder actions: Archive and Report-as-junk (move to the account's Archive/Junk mailbox via the same MOVE/COPY+EXPUNGE path) - backs the toolbar's Archive/Report buttons
- [x] Client-side snooze (hide a message and resurface it later - no IMAP-native equivalent, same approach as Gmail/Outlook desktop; tracked in a local SQLite `snoozed` table, re-checked on next sync rather than a dedicated timer) - backs the toolbar's Snooze button
- [x] Ribbon-style Home/View tab content - Home and View are now real, mutually-exclusive ribbon tabs in the menu bar row that switch the ribbon content row below. Home shows the command toolbar (New mail, Delete, Archive, Report, Reply, Reply All, Forward, Snooze); View is a new "Layout" group of pane-visibility toggles (Folder pane / Reading pane / Calendar overview). The tabs are Mail-only - they grey out while a Calendar/Config module is active (those keep their own non-tabbed command toolbars), and the layout toggles persist across restarts via GSettings (see Phase 5)
- [x] Message-list sorting (By Date / By Sender / By Subject, either direction, applied at the single `MessageListModel::repopulate` choke point) and a Favorites section pinned to the top of the folder tree, starred from the list header - both persisted across restarts via GSettings (see Phase 5)
- [x] Full-text search: SQLite FTS5 over cache + IMAP `SEARCH` fallback - a `gtk::SearchBar` revealed between the message-list header row and the column headers, opened by a new Home-toolbar Search button and Ctrl+F. Typing is debounced (300ms), then the list flips into a `MailView::Search` mode and shows instant results from a per-account SQLite FTS5 index (`search_fts` virtual table in `Cache`, populated on every `replace_messages`/`store_body`/`delete_message` and one-time backfilled from pre-search caches on open; `Cache::search` runs `MATCH` with a `sanitize_fts_query` that ANDs bare words and keeps `"`-quoted phrases, excluding snoozed messages). The live IMAP pass is `AccountCommand::SearchMailbox` (`UID SEARCH TEXT` + envelope fetch, SELECTing on demand, always answering with `AccountEvent::SearchResults` even for zero hits) covering the currently-open mailbox - or every account's Inbox from the unified view - for mail the local index hasn't seen. Esc/clearing the entry/folder-click exits back to the pre-search view; clicking a result opens it from any folder, because `FetchBody` now SELECTs its mailbox on demand instead of rejecting non-current folders.
- [ ] Internal drag-drop (move/tag) + external drag-out (`.eml`/`.zip`)
- [ ] Collapsible thread UI (reuse the folder tree's `TreeListModel` trick)
- [x] Color-tag keywords (`$Lookout-tag-*` namespace) + tag management - a tag is a client-side `{key, name, color}` definition (persisted as `$XDG_CONFIG_HOME/lookout/tags.json`, the same best-effort convention as calendar colours); assigning one stores the IMAP keyword `$Lookout-tag-<key>` on the message server-side (`AccountCommand::StoreKeywords`, a raw-atom `STORE +FLAGS.SILENT`/`-FLAGS.SILENT` sharing `store_raw_flags` with the system-flag path, patching the cache via `Cache::update_keywords` and re-emitting so the row repaints immediately). Keywords were already parsed into `EmailSummary.keywords` by the envelope fetch and persisted in the cache JSON, so assigned tags survive restarts and resyncs for free. Two assignment surfaces share one `build_tag_menu`: a Categorize `MenuButton` in the command toolbar (popover rebuilt on every show so checks track the selection) and a right-click context menu on message rows. Rows draw up to three `.message-tag-dot` color dots, colored by per-tag CSS rules `apply_tag_colors` keeps in sync; `message_row_key` includes the tag-keyword subset so a tag toggle triggers a rebuild, and `MessageListModel::refresh` re-renders after a recolor/rename (which change no keyword). A "Manage tags…" dialog (from either surface) adds/renames/recollors/deletes tags - `key` is derived once from the name at creation and stable across renames so server keywords keep matching; deleting a tag is non-destructive (only the definition is removed; keywords stay on the server and just stop displaying). Tags are case-insensitive server-side and keys are sanitized into legal RFC 3501 atoms (`lookout_core::sanitize_tag_key`), with the session additionally guarding against malformed atoms before they reach the wire. Servers must advertise `\*` in `PERMANENTFLAGS` to store arbitrary keywords; a rejection surfaces through the existing error toast.
- [x] Recipient-chip/autocomplete composer widget (see Phase 1's compose entry - `recipient_entry.rs`, with completions from a cache-backed address book)
- [x] Message flags (`STORE`) - `AccountCommand::StoreFlags` adds/removes IMAP system flags on a message, backing two things: opening a message in the reading pane marks it `\Seen` (bodies are fetched with `BODY.PEEK`, so the server never sets it), and the toolbar's Flag button toggles `\Flagged`, drawn as an amber marker in the message row. The command SELECTs the message's own folder when it isn't the open one - mark-as-read races folder switches, and the unified view mixes mailboxes - and the main loop's existing re-select puts the session back before the next IDLE. Successful stores patch the cached summary in place (`Cache::update_flags`) and re-emit from cache rather than re-syncing, so a mark-as-read costs one `STORE` and no fetch
- [x] Unified mailbox + cross-account views; full multi-account switcher
- [x] Batch actions + `Gtk.MultiSelection` - the message list's backing model is now `Gtk.MultiSelection` instead of `SingleSelection`, so `GtkListView` handles ctrl/shift-click natively; a per-row checkbox (`.message-checkbox`, revealed by hover/selection/a new header "Select" toggle via CSS opacity rather than layout `visible`, so it never reflows a row) is a second input onto the same selection, kept in sync both ways (`ListItem::connect_selected_notify` pushes model changes into the checkbox; the checkbox's own toggle calls `select_item`/`unselect_item` on a weak `ListItem` reference to avoid a ref cycle). `MessageListModel::selected_summaries()`/`SelectionKind::Multiple` generalize the old single-message API - `selected_summary()` keeps its exact old semantics (`Some` only for exactly one message) so Reply/Reply-All/Forward/Categorize correctly no-op on a multi-selection without any changes there. Delete/Archive/Report/Snooze/Flag/Unflag and a **new** Mark read/unread toolbar button (there was previously only the implicit mark-on-open) all batch through a new `selected_message_command_targets` resolver that groups the selection by `(account, mailbox)` and sends one new plural `AccountCommand` (`MoveMessages`/`SnoozeMessages`/`StoreFlagsMany`) per group - one batched IMAP `MOVE`/`COPY`/`STORE` over a comma-joined UID sequence-set and one resync per mailbox touched, not one round trip per message. Flag/Unflag and Mark read/unread use a Gmail-style aggregate direction computed once over the whole selection (any unflagged/unread → act on all; only all-flagged/all-read flips the other way), which reduces to today's exact per-message behavior for a single selection. Fixed a pre-existing gap while touching this: `MoveMessage`/`SnoozeMessage`'s handlers required the target mailbox to already be the session's currently-`SELECT`ed one and silently dropped the command otherwise (unlike `StoreFlags`, which already selects on demand) - both now select on demand too, so acting on a message from a mailbox other than the one currently open (e.g. from the unified "All Inboxes" view) works reliably instead of sometimes silently failing. The reading pane shows a new "N messages selected" placeholder page whenever more than one message is selected, and skips mark-as-read/body-fetch entirely in that case - structurally guaranteed by `selection_kind()` only ever producing `SelectionKind::Message` for exactly one selected row. `GtkMultiSelection` never autoselects row 0 the way `SingleSelection` did, which is a deliberate, desired behavior change: a freshly-opened or filtered-to-empty folder can now legitimately show no highlight, matching Gmail/Outlook rather than always forcing a highlight onto some row
